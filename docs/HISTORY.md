## 本地 JSON 向量库与本仓抽页（原 ADR-0001）

- **背景**：首批实现要先把手册送进可替换的本地库，接口先立住。
- **原因**：一上来绑 Milvus 太重；对照脚本里已有按段 / 按页切。
- **做法**：本仓 pymupdf4llm 抽页、印刷目录映射成知识块，Hash 或 HTTP embedding 写入本地 JSON。
- **意义**：离线这一段能从头跑到尾，向量后端可以后换。
- **废弃原因**：JSON 无索引、自管文件；解析一度迁出本仓。后继 ADR-0024（LanceDB）、ADR-0032（外仓 HTTP，已废）。PDF 抽页现由 ADR-0034 收回本仓。

## 源适配器按格式堆文件（原 ADR-0006 的模块形态）

- **背景**：手册 PDF 与网页 URL 进库路径不同。
- **原因**：一种源一个适配器会把分块约定打散，也难增 Office。
- **做法**：适配器输出可分块原文，共享步骤再切块。
- **意义**：页码和目录区间能留到引用。
- **废弃原因**：模块名「源适配器」仍在诱使按格式加文件。后继曾是 ADR-0016 的路由登记表（已废，见下条）；约定的对象仍有效，写在现行 ADR-0006。

## 抽取方式靠路由登记（原 ADR-0016 的登记表）

- **背景**：想增删 Office / URL 只改登记一行，抽取层按「基础信息 → 路由 → 方式 → 内容生成 → collect」拆文件。
- **原因**：当时预期会接多种格式，登记表看起来比按格式堆适配器轻。
- **做法**：`probe.py` / `route.py` / `entrance.py` 加 `METHOD_EXTRACTORS`；本阶段只登记 PDF。
- **意义**：文件很多，真正干活的只有 `methods/pdf.py`。
- **废弃原因**：本阶段只有 PDF，probe / route / entrance 是空壳。后继 ADR-0016 重写为四个 class；pymupdf4llm 单独落盘见 ADR-0039。

## 离线四段目录与 query/ 路由（原 ADR-0011 / 0013 / 0015 的位置）

- **背景**：对照实验台目录是 `ingest/` `query/` `utils/`。
- **原因**：要按离线层、在线层放代码，HTTP 也要有入口。
- **做法**：一度分成 `offline/{extract,chunk,embed,store}`，路由放 `query/ask_http.py` 或仓库根 `app.py`。
- **意义**：各层的预留位置有了名字，不再用产品仓目录。
- **废弃原因**：分块 / 向量化 / 存储应合并成一层；向量服务入库和提问共用，不该进 `offline/`；`query/` 与 `app.py` 内写路由已换成 `ask_server.py` + `online/router.py`。后继 ADR-0017、ADR-0018、ADR-0015、ADR-0020。分层目录本身仍有效，写在现行 ADR-0011。

## 在线插件启用才接入（原 ADR-0003 的插件开关）

- **背景**：实验台想随时取消改写、rerank、拒答、KV。
- **原因**：主路径固定、插件 I/O 稳定，避免改写入参形状。
- **做法**：开关一度放 `query_kb.py` 顶部，再迁 `online/slots.py`；图节点仍编译，布尔在层函数里读。
- **意义**：口头上说「可以拆」，实际多数开关关不掉层。
- **废弃原因**：假开关束缚开发，拨了不改路径。后继 ADR-0029（常量进 `conf/base.py`）、ADR-0030（删掉不起作用的开关）。主路径固定与对象形状仍有效，写在现行 ADR-0003。

## 公共配置写进 yaml 的 host 与端口（原 ADR-0021 的 yaml 范围）

- **背景**：各入口顶部重复 HOST / PORT / 路径。
- **原因**：想把公共配置收进一份 yaml。
- **做法**：host、端口、anyurl2text 地址进 `conf/config.yaml`。
- **意义**：入口不再各写一份端口。
- **废弃原因**：本机 ROOT、本服务端口、别人家地址不是同一类配置。后继 ADR-0022。密钥进 `.env` 仍有效，写在现行 ADR-0021。

## 品牌与车型写成约定的字段（原 ADR-0008 / 0014 的字段列举）

- **背景**：第一份样本是汽车手册。
- **原因**：问答页和表列需要筛品牌、车型。
- **做法**：`brand` / `car` 进知识块、LanceDB 列和意图提示词。
- **意义**：第一份样本能按车筛。
- **废弃原因**：样本领域不是库的领域，换手册就要改约定。后继 ADR-0026。一份库、来源是身份仍有效，写在现行 ADR-0008。

## 查询侧 KV 短路、词重叠重排、拒答总闸（原 USE_KV / USE_RERANK / USE_REFUSE）

- **背景**：目标架构把 KV、重叠重排、拒答画成可以关掉的预留位置。
- **原因**：对照实验想随时开关。
- **做法**：布尔进配置；KV 查询路径与生产入库不一致；重叠重排默认关；关拒答时空命中在召回抛错。
- **意义**：名字叫开关，行为与注释相反。
- **废弃原因**：不修通假路径，删掉不起作用的代码。后继 ADR-0030。当时 KV 存储还留着（原 ADR-0005）；后整段去掉，见 ADR-0040。

## 按文件名在 handbook 与 anyurl 之间切换

- **背景**：汽车手册 PDF 要走印刷目录。
- **原因**：路由需要决定哪份文件用哪套解析。
- **做法**：`HANDBOOK_NAMES` 写在配置或入库脚本，名单内 handbook，其余 anyurl。
- **意义**：第一份样本能抽出目录。
- **废弃原因**：文件名不是抽取层的约定，换样本就要改名单。后继 ADR-0031：按响应是否带印刷目录记方式名。名单若仍出现，只属于入库脚本样本开关，见 ADR-0019。

## 一决策一个 ADR 文件加现状补丁（2026-09-28）

- **背景**：grill-with-docs 一开始按编号各写一份 `docs/adr/NNNN-slug.md`。
- **原因**：一条决策往往只有一段话；改了只在文末加现状，旧选定仍像现行法。
- **做法**：32 个短文件 + 后写的 ADR 给先写的开例外。
- **意义**：当时能留下「为什么」，但 agent 读最早那句选定，约束跟不上代码。
- **废弃原因**：既记不全历史，也不能保证现行约束。后继 ADR-0033：一份 `docs/adr.md` 加重写日期；废决策进 `docs/history.md`。完整旧文曾在 `docs/adr/`，现已删。

## 抽取层只 HTTP 调 anyurl2text（原 ADR-0032）

- **背景**：抽页与印刷目录想集中在 anyurl2text，本仓只编排入库。
- **原因**：避免本仓再实现一套解析，可分块原文的约定仍由本仓 collect 写出。
- **做法**：`anyurl.py` 只 POST `/rag/extract/file`；本仓不抽页、不跑 pymupdf4llm。
- **意义**：PDF 与其它格式共用外仓一个入口。
- **废弃原因**：`scripts/ingest.py` 要对 PDF 独立抽页入库，8020 未起时手册进不了库。后继 ADR-0034 初版（先 PDF 本仓、非 PDF 仍 HTTP；同日又改成仅 PDF，见下一条）。

## 2026-10-10 · 非 PDF 仍 HTTP `/rag/extract/file`（ADR-0034 旧款）

- **背景**：ADR-0034 初版让 PDF 本仓抽页，Office / 纯文本仍打外仓 RAG 口。
- **原因**：手册主路径不依赖 8020，同时保留多格式入库口。
- **做法**：`route.py` 非 PDF → `methods/anyurl.py` POST `/rag/extract/file`。
- **意义**：PDF 手册可独立入库；其它格式共用外仓的接口约定。
- **废弃原因**：外仓下线 RAG 口并交还手册抽取；本仓与 anyurl2text 抽取解耦。现行 ADR-0034：仅 PDF，不预留空的 anyurl 实现文件。

## 2026-10-10 · 过滤标签按 AND 强制筛选（原 ADR-0026 的过滤那半）

- **背景**：入库抽出的动态标签想直接用来收窄检索范围。
- **原因**：`{field, value}` 看着像可过滤的列，强制筛选实现起来比调权简单。
- **做法**：召回前 `match_filters` 要求本轮每条标签都在块的 tags 里（多对 AND）；向量路靠 `source_in` 把允许的来源集合推回 LanceDB `where`。
- **意义**：文档级标签被当成按内容含义筛选来用；单文档库上看着像「有筛选」。
- **废弃原因**：同字段多值必然 0 命中（一个块只带其中一个值），空命中直接用拒答文案；文档级标签复制到每块，在单文档库上又是零收窄。后继 ADR-0035：来源强制筛选、标签按命中条数加权。

## 2026-10-28 · 仓库根直接摊 offline / online / embed（原 ADR-0011 的落点）

- **背景**：检索门面独立成 `frontend/` 之前，架构层放在仓库根。
- **原因**：当时按数据流分层即可，没有「前端一块地、后端一块地」的约束。
- **做法**：`offline/`、`online/`、`embed/` 在仓库根；`python -m online.server` / `python -m embed.server`。
- **意义**：层名即顶层目录名，import 短。
- **废弃原因**：前后端同仓后，根上再摊后端层会把地盘混在一层。后继 ADR-0038：`backend/` / `frontend/` / `docs/` / `service/`。offline / online 层名仍在 `backend/` 内，写在现行 ADR-0011。

## 2026-10-17 · 长驻服务入口在仓库根（原 ADR-0013）

- **背景**：多服务要有明确进程入口；`python 子目录/xxx.py` 会把 sys.path 指到子目录，`import conf` 失败。
- **原因**：根上 `python ask_server.py` 让解释器把仓库根放进搜索路径；层包只放实现，避免两份 `__main__`。
- **做法**：仓库根 `ask_server.py` / `embed_server.py`；包内不留启动同一进程的 `__main__`。
- **意义**：入口一眼能看见；`scripts/` 仍从子目录起、自己插上一级。
- **废弃原因**：根上表层文件过多，启动文件应挨着对应服务。后继 ADR-0036：入口在 `embed/server.py` / `online/server.py`，从仓库根 `python -m` 起，sys.path 仍是仓库根。

## KV 存储当可拆支线（原 ADR-0005）

- **背景**：手册进知识块、URL 抽 KV 两条离线流程互不相通。
- **原因**：短事实想精确匹配，又不想一上来双写两套库。
- **做法**：`kv_store.py` 与实验脚本可写 JSON；提问口不读、不把 KV 再编进向量库。
- **意义**：名义上留了 FAQ / 字段查询的位置。
- **废弃原因**：能稳拆的只有规格页上「一行一个冒号」的句子，覆盖面窄还干扰判断（节标题、tags、正文被当成三套检索对象）。后继 ADR-0040：支线删掉，规格句留在知识块里检索。
