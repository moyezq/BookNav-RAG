# 模型选型

本仓哪些能力靠外部模型、候选是什么、已测过什么、同系列怎么定尺寸。只记结论。

## 向量

入库和召回要把知识块编成向量。现网用 `BAAI/bge-m3`（1024 维），本机权重，进程在 `service/embed/`。Hash 向量只打通入库，不是语义模型，不算候选。本仓没有测过其它 embedding。

## 对话生成

意图分类、改写、标签候选、入库抽标签、闲聊与检索生成，共用一条 Chat HTTP，模型名 `deepseek-flash`。现网意图只分检索 / 闲聊两档。本仓没有对照测过其它对话模型。

## 决策模型

预备用决策模型替意图层做闲聊 / 结束 / 查库三分类，一次前向出校准概率；结束是用户收尾对话，不是召回后的拒答。现网仍走 Chat 两分类，决策服务不接提问口。

候选是 Kev 家族（0.8B / 4B / 9B / 27B）和 OmniJev（0.8B / 2B / 4B）。本仓已测的只有 Kev-0.8B：`service/kev08` 对中文探针三分类初步可用。Kev 其余尺寸和 OmniJev 只做了公开资料对照，没有下载、没有实测。

Kev-0.8B 留下，只因为它资源最小、能最快验证接口和中文三分类，不是因为准确率最高。官方文本决策从 4B 起才像样（域外准确率 0.697 → 0.838）；4B 官方 bf16 驻留 14.3 GB，本机 12 GB 卡不够。9B / 27B 本机不可行。OmniJev 是视觉决策模型，不选作当前文本意图。

## 尚未用模型的位置

拒答看余弦阈值，不用模型。重排只截断、不换序，交叉编码器未选型。图片 OCR 是预留文件，未选型。音视频入库明确不做。
