# 模型选型

本仓哪些能力靠外部模型、候选是什么、已测过什么、同系列怎么定尺寸。只记结论。

## 向量

入库和召回要把知识块编成向量。现网用 `BAAI/bge-m3`（1024 维），本机权重，进程在 `service/embed/`。本仓没有测过其它 embedding。8030 挂了时提问口走 BM25，不另造假向量。

## 对话生成

意图分类、改写、标签候选、入库抽标签、闲聊与检索生成，共用 `service/deepseek` 这一次非流式调用，模型名 `deepseek-flash`。分类和抽标签带 `json_object`。`deepseek-flash` 与 `deepseek-v4-pro` 都能用，不必按模型名关掉。各模块按返回的 kind 用，不自己打 HTTP。现网意图只分检索 / 闲聊两档。

## 决策模型

预备用决策模型接进意图识别与拒答，一次前向出多个类型化判断。结束是用户收尾对话，和拒答是两次判断。现网仍走 Chat 两分类，本阶段不接提问口；后续接线见 `docs/todo.md`。

候选是 Kev 家族（0.8B / 4B / 9B / 27B）和 OmniJev（0.8B / 2B / 4B）。本仓已测的只有 Kev-0.8B：`service/kev08` 对中文探针三分类初步可用。Kev 其余尺寸和 OmniJev 只做了公开资料对照，没有下载、没有实测。

Kev-0.8B 留下，只因为它资源最小、能最快验证接口和中文三分类，不是因为准确率最高。官方文本决策从 4B 起才像样（域外准确率 0.697 → 0.838）；4B 官方 bf16 驻留 14.3 GB，本机 12 GB 卡不够。9B / 27B 本机不可行。OmniJev 是视觉决策模型，不选作当前文本意图。

## 尚未用模型的位置

现网拒答看余弦阈值。后续计划改为决策模型参与拒答，见 `docs/todo.md`。重排只截断、不换序，交叉编码器未选型。图片 OCR、音视频入库明确不做。
